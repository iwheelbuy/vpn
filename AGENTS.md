# Agent Notes

## Purpose

Этот файл обязателен для любого агента или человека, который собирается менять проект.

Репозиторий хранит не "идеальную" реализацию VPN, а рабочий production-like baseline, который недавно был перепроверен вручную. Любые изменения должны исходить из презумпции: "сначала не сломать то, что уже работает".

## Source Of Truth

Текущая правда проекта такая:

- `step1.sh` и `step2.sh` отражают рабочий сценарий поднятия VPN.
- iPhone-клиент через `mobileconfig` сейчас подключается и работает.
- MikroTik RouterOS v6 используется как реальный клиент/маршрутизатор для IPsec-сценариев.
- Даже если некоторые решения выглядят старыми, избыточными или неидеальными, их нельзя менять без проверки на реальном сценарии.
- Есть отдельный active track по попытке убрать PrimeTel роутер и перевести схему на `ONT -> MikroTik`; он описан в [docs/primetel-bypass-runbook.md](/Users/macuser/Development/vpn1/docs/primetel-bypass-runbook.md).
- Этот track уже дал подтвержденный результат: для текущего подключения рабочее направление это `PPPoE + VLAN 42` с корректным `MAC` и реальными credentials; дальнейшие действия должны опираться на этот факт, а не начинать исследование заново.

## Working Assumptions

- Совместимость с iPhone важнее теоретической "чистоты" конфигурации.
- Совместимость с MikroTik RouterOS v6 важнее внедрения новых фич strongSwan по умолчанию.
- Проект должен оставаться переносимым между VPS-провайдерами; отличия ожидаются в сетевых правилах, доступе и bootstrap-шаге.
- Документация должна явно отделять generic-подход от provider-specific деталей.

## Change Rules

- Не переписывать скрипты целиком без необходимости.
- Не менять криптографические параметры, payload-поля `mobileconfig`, iptables-правила или RouterOS-команды без отдельного объяснения, зачем это нужно и как это проверять.
- Не считать отсутствие поддержки macOS installation profile "просто багом": это известное ограничение baseline, которое надо исправлять отдельно и аккуратно.
- Не коммитить `.p12`, приватные ключи, реальные IP, реальные пароли и реальные сертификаты.
- Любой рефакторинг должен сначала сохранять поведение один-в-один, а уже потом менять поведение.

## Preferred Workflow

1. Прочитать [README.md](/Users/macuser/Development/vpn1/README.md).
2. Прочитать [docs/current-state.md](/Users/macuser/Development/vpn1/docs/current-state.md).
3. Если запрос касается домашней сети, PrimeTel, ONT, bypass провайдерского роутера или прямого WAN на MikroTik, обязательно прочитать [docs/primetel-bypass-runbook.md](/Users/macuser/Development/vpn1/docs/primetel-bypass-runbook.md).
4. Только потом предлагать изменения.
5. Для каждой правки явно отметить:
   - это документирование;
   - это безопасный рефакторинг без смены поведения;
   - это поведенческое изменение, требующее ручной проверки.

## Manual Validation Expectations

Если в будущем меняется логика, желательно проверять как минимум:

- генерацию сертификатов и `mobileconfig`;
- подключение iPhone;
- импорт сертификата и IPsec-подключение на MikroTik;
- прохождение трафика через туннель;
- поведение selective/full-tunnel правил;
- влияние на `fasttrack`, `mangle` и policy activation в MikroTik.

## Current Documentation Targets

При развитии документации полезно держать отдельно:

- baseline, который точно работает сейчас;
- список известных ограничений;
- backlog маленьких безопасных улучшений;
- notes по различиям между провайдерами вроде Rabisu/AWS/других VPS.
- runbook активных исследований вроде PrimeTel bypass, где важно фиксировать текущий шаг, уже проверенные гипотезы и данные, которые еще нужно снять с железа.
